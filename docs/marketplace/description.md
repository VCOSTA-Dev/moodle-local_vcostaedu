# Moodle Marketplace entry: local_vcostaedu

## Name

VCOSTAEDU connection

## Short description

Prepares Moodle for VCOSTAEDU from one admin page (web services, service account, key) and
lets VCOSTAEDU log students in with safe one-time links.

## Long description

**VCOSTAEDU** is a free and open source academic platform that works alongside Moodle: it
keeps the academic records (students, classes, courses) and uses Moodle for the courses
themselves. This plugin is the Moodle side of that connection.

**What the plugin does**

- **Connect to VCOSTAEDU page.** A single admin page checks, item by item, everything the
  integration needs: web services, the REST protocol, a service user and role with exactly the
  capabilities the service functions use (29, listed in the reviewer guide, among them keeping
  a course's name, short name, id number, summary and category in step with the academic
  record), the external service with its functions, an access key and e-mail
  sending. Each line says what to do, and buttons fix it: turn on web services and REST, fix
  the role and the service, generate the key. When more than one action is pending, the page
  numbers them in order. The page then shows the two items to paste into VCOSTAEDU: the Moodle
  address and the key, with copy buttons.
- **Accounts found by e-mail.** For a school that already has students in Moodle, VCOSTAEDU
  finds each existing account by its e-mail address through a second function of the plugin,
  which answers only the account ids. The service account never gets to see the identity
  fields of the users.
- **One-time login links.** VCOSTAEDU asks Moodle, through the plugin's web service function,
  for a link that logs a student in without typing a password. Links are single use and expire
  after a short time (60 seconds by default). They are never issued for, and never open a
  session of, suspended, deleted, unconfirmed or blocked accounts, guests or site
  administrators; the account is checked again right before the session is created. A refused
  link never logs anybody else out, and the link only redirects inside the site.

**What depends on VCOSTAEDU**

Everything the plugin prepares is used by VCOSTAEDU, which calls the Moodle web services with
the key to create and update users, categories and courses, manage enrolments, read grades and
ask for login links. Without VCOSTAEDU the plugin only prepares Moodle; the login link function
can still be called by any system holding the key, as the reviewer guide shows.

**How to get the credentials**

There is no account to create anywhere else. The key is generated by the plugin's own page
(*Connect to VCOSTAEDU > Generate key*) and pasted into VCOSTAEDU, together with the Moodle
address.

**Installation**

Install the zip as usual. The installation creates the role `vcostaedu_ws`, the service user
`vcostaedu_ws` with that role for the whole site, and the external service "VCOSTAEDU" (short
name `local_vcostaedu`) with 17 functions; a role or user that already has that name is
reused. It does not switch on web services. If another external service already uses the name
"VCOSTAEDU" or the short name `local_vcostaedu`, the server check stops the installation and
explains what to do. Uninstalling removes the external service with its keys, the pending
login links, and the role and the user the plugin created; a role or user with the same name
that existed before stays. The texts are in English; a package with the Brazilian Portuguese
texts (`local_vcostaedu-<version>-ptbr.zip`) is available from the project repository until
the translation is in AMOS.

**Privacy**

The plugin keeps no personal data of its own. One-time login keys stay a few seconds in the
core user key table. VCOSTAEDU, an external system, reads and writes user, course, enrolment
and grade data through the web services; the privacy provider declares it.

**Requirements**

Moodle 4.5 to 5.3, MySQL/MariaDB or PostgreSQL. No other plugin, no command line tool.
