# VCOSTAEDU connection for Moodle (local_vcostaedu)

Português: [README.pt_br.md](README.pt_br.md).

## Description

This local plugin connects Moodle to VCOSTAEDU, a free and open source academic platform
that works alongside Moodle. It does two things:

1. **Prepares Moodle from the web interface.** The page *Site administration > Plugins >
   Local plugins > VCOSTAEDU > Connect to VCOSTAEDU* checks, item by item, what the
   integration needs (web services, REST, a service user and role, the external service, a
   key, e-mail sending) and fixes what is missing with a few buttons. It then shows the two
   items to paste into VCOSTAEDU: the Moodle address and the key.
2. **Student login through a one-time link.** VCOSTAEDU asks Moodle for a short-lived,
   single-use link and the student enters Moodle without typing a password. Links are never
   issued for, and never open a session of, suspended, deleted, unconfirmed or blocked
   accounts, guests or site administrators.

The plugin only uses the standard Moodle web services API. It has no dependency and does
not contact any server.

## Requirements

- Moodle 4.5 to 5.3 (tested on 4.5.16, 5.0.12, 5.1.9, 5.2.5 and 5.3.1), with MySQL/MariaDB
  or PostgreSQL, and the PHP version that Moodle version asks for.
- No other plugin and no command line tool.
- Students need an authentication method that is enabled on the site; VCOSTAEDU creates
  them with manual accounts.

## Installation

Install the zip through *Site administration > Plugins > Install plugins*, or copy the
`vcostaedu` folder by hand and run the upgrade. The destination depends on the Moodle
version: `local/vcostaedu` on Moodle 4.5 and 5.0, `public/local/vcostaedu` on Moodle 5.1
and later. Then open *Connect to VCOSTAEDU* and follow the diagnosis.

There are two packages: `local_vcostaedu-<version>.zip` (English only, the one in the Moodle
Marketplace) and `local_vcostaedu-<version>-ptbr.zip` (the same, with the texts in Brazilian
Portuguese).

Step by step guide with screenshots: [docs/INSTALL.md](docs/INSTALL.md).

Something worth knowing before installing:

- The installation creates the role `vcostaedu_ws`, the service user `vcostaedu_ws` with that
  role for the whole site, and the external service "VCOSTAEDU" (short name
  `local_vcostaedu`) with 17 functions. A role or user that already has that name is reused.
  If another external service already uses the name "VCOSTAEDU" or the short name
  `local_vcostaedu`, the installation stops on the server check page and says what to do.
- Web services and REST are not switched on by the installation; a button on the connect
  page does it, when the administrator decides.
- Uninstalling removes the external service with its keys, the pending login links, and the
  role and the user the plugin created; a role or user with the same name that existed before
  stays.

## External service

VCOSTAEDU is a free and open source academic platform. With the key generated on the
*Connect to VCOSTAEDU* page, VCOSTAEDU calls the Moodle web services to create and update
users, categories and courses, enrol and unenrol students, read enrolments and grades, find
accounts that already exist by e-mail (the plugin's function `local_vcostaedu_find_users_by_email`
answers only their ids), and ask for login links.

- What depends on VCOSTAEDU: everything the plugin prepares is used by VCOSTAEDU. Without
  it, the plugin only prepares Moodle; the login link function can still be called by any
  system holding the key.
- Credentials: there is no account to create elsewhere. The key is generated by the plugin
  page itself and pasted into VCOSTAEDU.
- Testing without VCOSTAEDU: [docs/REVIEW.md](docs/REVIEW.md) shows how to do everything
  with plain web service calls.

### E-mail and enrolments

Moodle sends the course welcome message to a student on every manual enrolment call,
including suspending, reactivating or repeating an enrolment, when the course has a teacher.
If Moodle cannot send e-mail, each of these calls saves the change and still answers with
the error "Message was not sent.". VCOSTAEDU treats that answer as a warning. To avoid it,
set up outgoing mail, or turn off the welcome message in *Site administration > Plugins >
Enrolments > Manual enrolments*. The connect page warns about it and the plugin does not
change these settings.

## Privacy

The plugin stores no personal data of its own. One-time login keys stay a few seconds in the
core user key table and are deleted when used or expired. VCOSTAEDU, an external system,
reads and writes user, course, enrolment and grade data through the web services; the privacy
provider declares it, with each kind of data.
